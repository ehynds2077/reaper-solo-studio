# Bounce library

Open **Mix → Bounces**. **Bounce mix + instrumental** asks for a version name and
optional notes, then renders the full song (default) or the time selection.
**Vocal tracks…** selects every track to exclude from the instrumental. Names
containing vocal/vox/BGV/BV are initially suggested, including scratch vocals.
Review the selection for each song, especially if vocals are routed through
folders or dedicated effects returns. No selected vocals means identical mixes.

Each version goes into `~/Desktop/Solo Studio Mixes/` and contains:

- Full mix and instrumental, stereo 48 kHz / 24-bit WAV, with a two-second tail.
- Named 256 kb/s AAC `.m4a` files for texting, AirDrop, and phone listening.
- `Session.RPP`, capturing the working project including unsaved edits at export.
- `Instrumental session.RPP`, with the selected vocal tracks muted.
- Version title, notes, date, range, excluded vocal tracks, and archive status.

**Play full / Instrumental**, **Pause / Resume**, and **Stop** audition old bounces
inside the panel. Space pauses/resumes the bounce while this view has focus.
Audition uses the Mac's selected audio output, which may differ from REAPER's
interface. Starting the REAPER transport, switching projects, or closing the
panel stops the audition. **Show files** opens the version folder for sharing.
**Open session copy** opens the archived full mix as a new unsaved project tab;
the working song stays open and Save asks for a new filename to protect the archive.

Rendering takes place in a disposable project copy. The working mix, render
settings, arming, cursor, and AI comparison remain intact. Stop transport and
finish any active AI pass first. Clear solos before exporting. Cancelled or
failed renders stay marked incomplete and cannot masquerade as finished mixes.
A failed packaging operation can be retried without re-rendering complete WAVs.

Source recordings from all item takes and freeze sources are copied into the
library's `_Media` folder. Identical files are shared across versions; copies
are independent of the originals. Both RPP files point to those preserved copies.
**Move or back up the entire Solo Studio Mixes folder together**, including
`_Media`. Installed plugins, licenses, and plugin-managed sample libraries still
need to be available when reopening. Nested REAPER subprojects currently fail
archiving explicitly rather than creating a misleadingly complete backup.

The library groups by saved song path. Reopening a snapshot retains its original
song's history. Renaming/moving the working RPP currently starts a separate
library grouping; the older files remain on the Desktop.

## Installation

Copy `Bounces/library.py` into `Scripts/Solo Studio/Bounces/` alongside the
installed Lua scripts. This macOS version uses `/usr/bin/python3`, `/usr/bin/afplay`,
and FFmpeg (from PATH, `/opt/homebrew/bin`, or `/usr/local/bin`). It needs no
OpenRouter account, API connection, browser, or new REAPER extension.

## Checks

`PYTHONDONTWRITEBYTECODE=1 python3 Bounces/test_library.py` checks immutable copies,
source-path rewriting, retries, missing recordings, and packaging failures.
`lua "$PWD/Tests/Bounce library controls.lua"` checks UI selection and playback
locks. `Tests/Run bounce checks.lua` runs real native exports in a disposable
project, reopens the archived RPP, and checks cancellation and exact preservation
of the user's project. Synthetic input WAVs are generated by
`python3 Tests/make_fixtures.py`.

The native export uses [REAPER's documented project-copy and render APIs](https://www.reaper.fm/sdk/reascript/reascripthelp.html#Main_SaveProjectEx).
